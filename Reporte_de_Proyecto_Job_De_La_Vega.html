Proyecto Integrador Parcial 1: Pipeline CI/CD Automatizado para API REST

Introducción

En la industria actual del desarrollo de software, la entrega de valor constante y libre de errores es un pilar fundamental para el éxito de cualquier proyecto tecnológico. La adopción de la cultura DevOps y, en específico, la implementación de flujos de Integración Continua (CI) y Despliegue Continuo (CD), ha transformado la manera en que los equipos de ingeniería construyen, prueban y liberan aplicaciones. El presente proyecto integrador documenta el diseño, configuración y puesta en marcha de un pipeline CI/CD completamente automatizado para una API RESTful desarrollada en ASP.NET Core (.NET 10 SDK) con persistencia en SQLite mediante Entity Framework Core y un servidor concurrente TCP Sockets, con el objetivo de eliminar los procesos manuales y garantizar que cada cambio en el código fuente sea evaluado rigurosamente antes de llegar a un entorno de producción.

La Integración Continua (CI) permite que múltiples desarrolladores integren su código en un repositorio compartido de manera frecuente. En este proyecto, dicha integración se gestiona mediante GitHub Actions, una plataforma que actúa como orquestador para interceptar los eventos de tipo push en la rama principal. Al detectar un cambio, el sistema ejecuta de forma automática una suite de pruebas unitarias construida con xUnit y FluentAssertions. Este paso es crítico, ya que asegura que las nuevas implementaciones no rompan la funcionalidad existente. Solo si el código aprueba esta barrera de calidad, el flujo avanza hacia la fase de empaquetado, donde la aplicación se compila y encapsula en una imagen de contenedor mediante Docker y se publica en un registro de artefactos (Docker Hub).

Por su parte, el Despliegue Continuo (CD) cierra el ciclo de vida del desarrollo al llevar el artefacto empaquetado directamente hacia la infraestructura en la nube sin intervención humana. En esta implementación se aprovisionó una instancia de Ubuntu Server en Amazon Web Services (AWS EC2). A través de conexiones seguras mediante

De esta manera, el proyecto demuestra el dominio técnico sobre herramientas de backend y cloud computing, y consolida un entorno de trabajo auditable y listo para escalar.

Fase 1: Desarrollo y calidad de código

Se finalizó la construcción de la API REST incorporando 13 endpoints funcionales que administran Productos, Categorías, respaldos de base de datos (`/api/backup`), limpieza (`/api/vaciar`), monitoreo (`/api/health`) y un socket TCP concurrente en el puerto 6061, superando el mínimo requerido. Para garantizar la fiabilidad del software, se implementaron 25 pruebas unitarias automatizadas con xUnit y FluentAssertions.

Fase 2: Integración Continua (CI)

Se configuró el archivo main.yml en el repositorio para orquestar el flujo de GitHub Actions. El pipeline descargó el código, configuró el SDK de .NET 10, restauró paquetes, ejecutó las 25 pruebas unitarias y, al ser exitosas, construyó la imagen a partir del Dockerfile. La imagen fue publicada en Docker Hub (raydererizo/webapp) etiquetada con la versión latest y el hash del commit para mantener la trazabilidad.

Fase 3: Despliegue Continuo (CD) en AWS

Utilizando llaves .pem gestionadas exclusivamente a través de GitHub Secrets, el pipeline se conectó a la instancia EC2, descargó la imagen actualizada y reinició el contenedor mapeando el tráfico del servidor al puerto 80 (hacia el puerto interno 8080 del contenedor) y al puerto 6061 para sockets TCP.

Conclusión

La implementación de este pipeline CI/CD demuestra de manera práctica cómo las prácticas de DevOps reducen los riesgos asociados con la liberación de software. Al delegar la ejecución de pruebas, el empaquetado en contenedores Docker y el despliegue en AWS EC2 a un orquestador como GitHub Actions, se elimina la posibilidad de fallos por error humano en tareas repetitivas. Esto permite enfocar el desarrollo en la lógica de negocio, con la certeza de que el pipeline rechazará cualquier código que no cumpla con los estándares de calidad definidos.

Dominar estas arquitecturas resulta fundamental para la ingeniería de software moderna. La separación de responsabilidades, el manejo seguro de credenciales mediante secretos y el uso de imágenes inmutables favorecen la disponibilidad del servicio y la escalabilidad del sistema a futuro. Este proyecto consolida las bases técnicas necesarias para gestionar entornos de producción reales.
